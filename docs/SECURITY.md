# Security model

A presentation is **untrusted code**: it may be generated by an AI, downloaded, or crafted to attack whoever edits it. Deckhand must be safe to open it, and must never write anything the user did not ask for.

## Trust boundaries

```
 editor UI (deckhand-app://ui, sandboxed renderer, strict CSP, contextBridge only)
      │  typed + zod-validated IPC, sender-frame checked        ┌────────────────────────────┐
      ├──────────────────────────────────────────────────────►  │ main process (files, dialogs)│
      │  MessageChannel port, handed to ONE origin              └────────────────────────────┘
      ▼
 live view iframe (deckhand-doc://<random>, sandbox, own origin)  ← hostile deck code runs here
```

## Threats and controls

| Threat | Control | Verified by |
|---|---|---|
| Deck script reaches editor DOM/IPC/Node | Distinct origin per document; iframe `sandbox`; `contextIsolation`, `sandbox`, `nodeIntegration:false`; bridge exposes 16 fixed functions; no bridge in subframes (`nodeIntegrationInSubFrames:false`) | `security.spec` hostile deck: `typeof window.deckhand/electron/require/process` all `undefined`; `parent.document` throws |
| Deck hangs or exhausts the UI | Live view in its own process; heartbeat watchdog (5 s) with "Reload / Reload with scripts off" | hostile deck loops 25 s, UI click < 3 s; watchdog bar shown; scripts-off reload |
| Deck reads local files (`file://`, `../`, encoded/double-encoded traversal, absolute, UNC, drive letters, ADS, device names) | `sanitizeRequestPath` (decode once, reject `..`, `\`, NUL, `C:`, `//`, `::$DATA`, reserved names) → `realpath` → prefix containment (case-aware); `file:`/`ftp:` requests from deck frames cancelled | 16 hostile URLs via main-process `net.fetch`; junction escape → 403; unit fuzz of the path function |
| Deck navigates/opens windows/downloads | `setWindowOpenHandler` deny, `will-navigate`/`will-frame-navigate` deny, `will-attach-webview` deny, `will-download` cancelled, sandbox without `allow-top-navigation`/`allow-popups`/`allow-downloads` | `window.open` → null, `top.location=` blocked, window count stays 1, editor URL unchanged |
| Deck requests camera/mic/geolocation/notifications/clipboard | Permission request/check/device handlers return false | geolocation/notification/camera/clipboard denied |
| Deck forges messages to the editor | Agent talks over a private `MessagePort` delivered by exact-origin `postMessage`; the agent claims it in the capture phase and hides it; every message is zod-validated with size limits (`ui/session.ts`); a deck that is not first cannot read the token (script removes itself, token never in DOM); live HTML is served once per single-use key | forged `postMessage` and fake `deckhand:init` ignored; deck `fetch(location.href)` gets no agent |
| External content leaks/tracks | Trust setting Allow/Block per document, enforced by `webRequest` on the requesting **frame** | local HTTP server sees requests when Allow, none when Block |
| Editor UI XSS | CSP `default-src 'none'; script-src 'self'` (no `unsafe-eval`, no inline scripts), set on the protocol response; no remote code | injected inline script does not run; header asserted |
| Malicious clipboard/pasted/edited HTML | Allow-list sanitizer rebuilds markup (no scripts, handlers, `javascript:`/`data:` links, `url()` styles, `<style>`, SVG/MathML) | 3000-case fuzz + targeted cases |
| Injection through values we write into the file (CSS values, attribute values) | `isSafeCssProp/Value` (no `;`/`{}`/`<>`/`\`/comments/`@import`/`expression`/`javascript:` outside strings and parens); attribute escaping; agent script `</script>` escaping | unit tests |
| Renderer asks main to write/read arbitrary paths | Renderer never supplies a write path: saves go to the path the main process opened; Save As uses a native dialog; open paths validated (absolute, `.html/.htm`, no UNC/NUL, ≤ 4096) and realpath'ed; recovery keys are 16-hex only | IPC argument tests |
| Open-external abuse | Only `http/https/mailto`, after a confirmation dialog | `javascript:`/`file:` refused |
| Data loss / corruption | Atomic save (temp + fsync + rename, backup + in-place fallback); `assertNoArtifacts` refuses to save editor ids/agent text; AutoRecover stored in app data, never beside the deck | byte-identical no-op saves on every corpus deck; deck folder unchanged by editing |
| Tampered application | Electron fuses: `RunAsNode`, `NODE_OPTIONS`, `--inspect` off; cookie encryption; asar integrity; load only from asar | fuse state read from the shipped binary; `ELECTRON_RUN_AS_NODE=1 -e` does not execute |
| Supply chain | Exact Electron pin, lockfile, bundled UI (no CDN), `npm audit` in release checklist | — |

## Known limitations (be aware)

- With "Allow external content" (default, per spec) a deck can contact the internet. Switch it off per document in View. Protected View for downloaded files (SPEC SEC-06, P1) is **not implemented yet**.
- The deck always runs scripts unless switched off per document; scripts are sandboxed but run.
- Outside-folder files are always blocked; the per-file "Allow" choice (SEC-03) is not implemented.
- Packaged builds are unsigned; Windows SmartScreen / macOS Gatekeeper will warn.
- macOS and Linux run the full e2e suite in CI (GitHub-hosted runners); they have not been exercised by hand.
- `eval`-free CSP applies to the editor; decks can use whatever they like inside their own sandbox.
